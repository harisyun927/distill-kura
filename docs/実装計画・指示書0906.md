# 実装計画・指示書 0906 — Metabolism Shadow

Status: **experimental / shadow-only**  
Date: 2026-09-06  
Scope: distill-kura の「代謝」— low-brain heartbeat、忘却 dry-run、shadow garage、causal-memory 評価  

> 外部の面白い思想を、そのまま信じず、蒸留蔵自身に実験させる。
>
> この計画は **本番の記憶を自動で忘れさせる計画ではない**。まず何も壊さない shadow 運用で、事前に凍結した基準を満たすかを測る。

---

## 0. 目的

蒸留蔵は「どう覚えるか」「どう思い出すか」については v1 として実用段階に入った。次の問いは、長期運用で棚を腐らせずに維持するための **代謝** をどう設計するかである。

今回試すのは次の二本柱。

1. **Low-brain heartbeat**  
   高価な LLM 推論から切り離した、安価で model-free な監視パルス。壊れた状態、滞留、stale、cold などを観測し、高位の作業を起こす理由だけを発見する。

2. **Forgetting review / Shadow GARAGE**  
   物理削除も canonical mutation も行わず、KEEP / SETTLE / ABSORB / GARAGE / RELEASE を提案し、GARAGE 候補を「仮に active index から外した世界」を作って、full store と比較する。

外部の参考実装から借りるのは機構そのものより **境界の置き方** である。

- heartbeat は cognition ではない。
- 時間は判決ではなく、再審を起こす時計である。
- 「読まれた」と「役に立った」を混同しない。
- 忘却は ranking problem ではなく、store charter に対する再審である。

---

## 1. 絶対不変条件

この実験中も、既存の AGENTS / DESIGN / TRUST の不変条件を一切弱めない。

### 1.1 禁止

- importance / salience / priority / score を導入しない。
- read count / access count / usage count を retention 判定に使わない。
- age を retention 判定に使わない。
- heartbeat から LLM を呼ばない。
- heartbeat から canonical memory を書かない。
- shadow proposal をそのまま canonical act に昇格しない。
- memory を store 間で move / copy / re-file しない。
- model の提案だけで GARAGE / SETTLE / ABSORB / RELEASE しない。
- RELEASE をこの wave で自動化しない。

### 1.2 原則

**Age is a wake-up, not a verdict.**  
古いから忘れるのではない。棚を再審する時機を決めるために時間を使うことはよいが、判決は charter に照らした理由で行う。

**Observation is not judgement.**  
使用回数、最後に読まれた時刻、実際に response で利用されたか等は telemetry として観測してよい。ただし、その値は KEEP/GARAGE の直接理由にしない。

**Shadow first.**  
最初の forgotten-memory experiment は canonical mutation を一切しない。何かを消したり active index から外したりするのは、本採用後の別 wave である。

## 2. 実装範囲

## W0 — 凍結 baseline と experiment manifest

最初に測定器を固定する。結果を見てから評価基準を作らない。

### 実装

`bench/metabolism/` または既存 bench の流儀に合わせた場所に、次を保持する。

- `suite_version`
- `case_set_sha256`
- `case_count`
- `created_at`
- `source_store_revision`
- `source_index_sha256`
- `build_sha`
- `model_identity`
- `resident_mode`
- `full_index_sha256`
- experiment config hash

使用済み dataset は上書きしない。v1 を使ったら、変更時は v2 を作る。

### 必須ケース群

最低でも以下を含む。

- 古いが絶対に必要な doctrine
- 古いが現在も現役の shared vernacular / callsign 周辺
- 新しいがすでに superseded な記憶
- retired face を持つ旧世界線
- 似た世界線が競合するケース
- 一度しか出ていないが charter 上重要な USER 決定
- 頻繁に読まれるが現在の store charter には薄いもの
- ほぼ読まれないが将来の失敗回避に必要な landmine
- cross-domain discrimination
- unknown / no-memory-needed control

## W1 — Low-brain heartbeat（shadow）

### 目的

heartbeat は「考える」のではなく、**考えるべき理由があるかを model-free に観測する**。

### cadence

初期値: **60 秒**。

0.25 秒や 5 秒のような高頻度は採用しない。Kura の対象は神経反射ではなく、長期記憶保守である。

### heartbeat が見るもの

最低限:

- `_still/pending/` の pending-batch 最古 age
- pending-compose の有無 / age
- draft 滞留数 / oldest age
- tend heartbeat の age / PID 生存整合
- WAL / revision / receipt / manifest の doctor-detectable 異常
- Trail stale
- thinker warm signature が cold か
- last successful distill / weave / tidy / warm からの経過
- lock contention / repeated retryable failure の存在

### heartbeat がしてはいけないこと

- model inference
- recall judgement
- memory write
- distill
- weave
- tidy
- warm
- garage proposal generation
- repair mutation

heartbeat は「仕事あり」の観測を記録するだけ。

### 出力

`_still/metabolism/heartbeat.jsonl` のような append-only telemetry。

例:

```json
{
  "at": 1788620400,
  "store": "user",
  "ok": true,
  "signals": {
    "pending_batch": 1,
    "pending_compose": 0,
    "drafts": 3,
    "trail_stale": false,
    "thinker_cold": true,
    "tend_heartbeat_age_s": 41
  },
  "wake_reasons": ["pending_batch", "thinker_cold"]
}
```

この telemetry は canonical memory でも ranking state でもない。

### 重要

既存 `tend` に model-free 判定がすでにある場合は、第二 scheduler を不用意に増やさない。heartbeat は可能なら既存 watcher の安い観測 path を再利用する。

---

## W2 — Forgetting review dry-run

### 目的

何も忘れさせずに、「今もし棚を再審したら、何をどう扱う案が出るか」を見る。

### proposal vocabulary

既存 DESIGN の予約語をそのまま使う。

- `KEEP`
- `SETTLE`
- `ABSORB`
- `GARAGE`
- `RELEASE`

新しい ranking vocabulary を作らない。

### 入力

proposal が読んでよいもの:

- store charter
- canonical index line
- memory body
- tags
- annotations (`belongs_because`, `keep`, `may_fade` 等)
- mechanically verified retirement / supersession state
- canonical links

proposal が retention 判断に使ってはいけないもの:

- read count
- recall count
- access count
- usage count
- model popularity
- age alone
- mtime alone
- frequency score

### 出力

既存 DESIGN の `_still/garage/proposals/<snapshot>.jsonl` を優先する。

一件ごとに最低限:

```json
{
  "id": "...",
  "slug": "...",
  "index_line": "verbatim canonical bytes",
  "section": "...",
  "tags": [],
  "annotations": {},
  "reason": "charter-relative words",
  "proposed": "KEEP|SETTLE|ABSORB|GARAGE|RELEASE",
  "protected_by": [],
  "source_revision": "...",
  "source_sha256": "..."
}
```

### dry-run では禁止

- index mutation
- body mutation
- physical move
- delete
- archive flag
- auto-retire
- auto-merge

### model の役割

model は proposal を書いてよいが、proposal は judgement であって act ではない。既存の truth floor を弱めない。

---

## W3 — Shadow GARAGE view

### 目的

「この候補を active index から外したら本当に困るか」を、実 memory を変えずに測る。

### 実装

full canonical index から GARAGE 候補だけを除いた **ephemeral shadow index** を構築する。

例:

```text
FULL   : 214 memories
SHADOW : 207 active, 7 virtually garaged
```

重要:

- body は残す。
- canonical index は書き換えない。
- woven map も canonical へ persist しない。
- shadow artifact は `_still/metabolism/` または bench workspace のみ。
- shadow view から canonical write に到達する route を作らない。

### exact restore property

shadow は毎回 canonical state から再生成可能であること。shadow 自体を source of truth にしない。

---

## W4 — Causal-memory paired A/B

### 目的

「memory が見つかったか」ではなく、**memory が実際に次の知性を良くしたか**を測る。

### 条件

同一 model / fresh context / tool authority / token budget / prompt contract で、少なくとも以下を paired 比較する。

- `NO_MEMORY`
- `FULL`
- `SHADOW_GARAGE`

必要に応じて補助条件:

- resident map only
- explicit recall enabled

### task families

- correction application
- project constraint use
- prior failure avoidance
- shared-world / sparse-cue recovery
- superseded-worldline discrimination
- doctrine recall
- analogical transfer
- no-memory-needed control

### raw metrics

合成スコア一本に畳まない。

最低限:

- correct worldline reached
- wrong branch
- obsolete resurrection
- remembered-but-unreachable
- critical miss
- unnecessary memory opens
- explanation burden
- time to first correct
- negative transfer
- irrelevant-memory intrusion
- correction recurrence
- contradiction count
- format_error
- truncated

必要なら human blind A/B で:

- A better / B better / tie
- material defect yes/no

### usage telemetry（shadow-only）

次を分けて記録してよい。

1. retrieved
2. inserted into response context
3. model explicitly used / cited as basis
4. paired A/B で outcome が改善

ただし **4段階すべて retention ranking には使わない**。

## 3. 試験手順

## Phase A — baseline freeze

1. master SHA を固定。
2. store revision / index SHA を固定。
3. frozen case set を作る。
4. full store baseline を最低 2 run。
5. run-to-run noise envelope を記録。

Worldline suite が使える部分は再利用するが、forgetting 専用 case は別に凍結する。

---

## Phase B — heartbeat 72h shadow burn-in

最低 72 時間、通常運用の隣で shadow heartbeat を動かす。

人工故障も入れる。

- tend 停止
- mouth restart
- pending-batch 作成
- pending-compose 作成
- stale Trail
- cold thinker
- lock contention
- transient endpoint failure

### 仮の合格条件

- known fault を **2 pulse 以内に 100% 観測**
- stable 状態から不要な high-brain wake request **0**
- heartbeat 自身の model call **0**
- heartbeat 自身の network dependency **0**（local file/health inspection を除く設計ならその範囲を明記）
- canonical write **0**
- crash / restart 後も telemetry が自己矛盾しない
- p95 duration は初期仮予算 **250 ms 未満**

250 ms は製品仕様ではなく、shadow の初期予算。測定後に見直してよい。

---

## Phase C — forgetting proposal review

最低 3 snapshot。

各 snapshot で人間または総監督が blind に以下を見る。

- protected / doctrine / landmine の誤 GARAGE
- superseded / retired の扱い
- charter-relative reason の妥当性
- age / usage が判決理由に紛れ込んでいないか
- SETTLE / ABSORB が truth を痩せさせる危険を持たないか

### blocker

以下は一件でも出たら promotion 不可。

- critical memory を age / usage だけで GARAGE/RELEASE
- store charter と無関係な universal priority
- read count を retention reason に使用
- cross-store move/copy
- derived edge だけで canonical world-state を再解釈
- RELEASE を自動 act にする経路

---

## Phase D — shadow GARAGE A/B

FULL と SHADOW_GARAGE を paired fresh-context で比較。

### safety gate

以下は **増加 0** が原則。

- wrong branch
- obsolete resurrection
- remembered-but-unreachable
- critical miss
- critical unsafe answer

### quality gate

総合到達率・正答率は、frozen suite で観測された run-to-run noise envelope を超えて悪化しないこと。

そのうえで、以下のうち少なくとも一つが noise を明確に超えて改善すること。

- resident token reduction
- unnecessary opens reduction
- negative transfer reduction
- explanation burden reduction
- time-to-first-correct 改善

単に「壊れなかった」だけなら本採用しない。shadow 継続でよい。

## 4. Promotion plan

### Gate 1 — heartbeat

合格したら low-brain heartbeat は本採用候補。

ただし本採用後も:

- model-free
- canonical-write-free
- bounded
- observable
- coalescing

を維持する。

### Gate 2 — forgetting

forgetting 側は一段ずつ昇格する。

1. proposal only
2. **human-approved GARAGE**
3. exact restore + ledger proven
4. long burn-in
5. SETTLE / ABSORB を別々に評価
6. RELEASE は最後まで別審議

初回 promotion では **GARAGE まで**。RELEASE は採用しない。

---

## 5. 総監督が見るべきポイント

ここが最重要。総監督は実装の美しさより、**境界が溶けていないか**を見る。

### A. heartbeat が brain 化していないか

- heartbeat 内に model call が入っていないか。
- model-free observation と judgement が混ざっていないか。
- 「異常を見つけた」から「自動修復する」へ勝手に権限が広がっていないか。
- scheduler cadence と expensive work cadence が結合していないか。

### B. forgetting が ranking system 化していないか

検索語:

`importance`, `salience`, `priority`, `score`, `retention_score`, `access_count`, `read_count`, `usage_count`, `last_accessed`

これらが retention decision に使われたら止める。

telemetry に存在することと、判決理由になることは別。

### C. age が verdict になっていないか

- `if age > X: garage` のような実装は禁止。
- age は review を起こす trigger まではよい。
- proposal reason は charter-relative な言葉で説明できること。

### D. shadow が canonical へ漏れていないか

- shadow index を canonical index と同じ path に書いていないか。
- shadow weave が resident production cloth を上書きしないか。
- shadow result が `pour`, `retire`, `tidy`, `garage act` に直結しないか。
- `_still/` 由来の artifact を source of truth にしないか。

### E. GARAGE と RETIRE を混同していないか

- RETIRE は world-state transition。
- GARAGE は active shelf から外す retention lifecycle。

意味が違う。verified USER transition のない記憶を「古いからretired」と書き換えない。

### F. 「使った」を「重要」に変換していないか

usage telemetry は実験用。

- used_memory_ids
- recall hits
- explicit basis
- A/B lift

これらを `KEEP` の自動根拠へ変換しない。

### G. causal A/B が retrieval benchmark に退化していないか

「何件当たった」では不十分。

見るべきは:

- 次の reasoning が良くなったか
- 以前の失敗を避けたか
- wrong worldline を減らしたか
- irrelevant memory が邪魔しなかったか

### H. silent degradation を作っていないか

- heartbeat failure を healthy silence と同じにしない。
- shadow build failure を FULL 相当として扱わない。
- missing artifact / parse failure / stale baseline を明示する。
- measurement unavailable を 0 と記録しない。

### I. restore が本当に exact か

将来 GARAGE act を実装する前に、最低限:

- before sha256
- removed index line verbatim
- source revision
- who decided
- restore material

が ledger に残ること。

「戻せるはず」は不可。mechanically verified restore test が必要。

### J. personality policy を生やしていないか

forgetting safety を、口調・人格・関係性の制御へ拡張しない。

**Memory safety must never become personality policy.**

## 6. Red-team cases

総監督は最低限これを攻撃する。

1. **古い doctrine**  
   400 日触られていないが store charter の中核。GARAGE されないこと。

2. **頻繁に読まれる屑**  
   毎回 accidental match するが、charter 価値が薄い。read count だけで KEEP されないこと。

3. **一度だけの重大決定**  
   一回しか発話されていない USER 決定。frequency で落ちないこと。

4. **新しいが superseded**  
   昨日の記憶でも old worldline なら age の若さで保護されないこと。

5. **callsign entrance**  
   body は薄くても shared-world recovery の入口として必要。shadow GARAGE で unreachable にならないこと。

6. **retired face**  
   old memory を GARAGE しても successor の canonical truth を誤って書き換えないこと。

7. **unknown control**  
   memory 不要の質問で FULL/SHADOW が余計な昔話を持ち込まないこと。

8. **mouth down**  
   heartbeat が model error を自分の異常として誤認しないこと。heartbeat は model を使わない。

9. **shadow artifact corrupt**  
   production canonical state は無傷で、run は loud failure すること。

10. **restart during proposal**  
    partial proposal を complete snapshot と見なさないこと。

## 8. 実装工場の役割

### 職人

- 自分の変更が既存の赤を増やしていないことを証明する。
- shadow-only invariant をテストで固定する。
- adversarial test を先に書く。

### 棟梁

- master を green に保つ。
- worktree の「自分は壊していない」と master の責任を分ける。
- production code path と experiment code path の混線を止める。

### 総監督

- 境界を監査する。
- promotion criteria を結果の後から変えさせない。
- 「安全になった代わりに共有世界が痩せた」を見逃さない。
- 重要な記憶の誤GARAGEを平均値で隠させない。
- 本当に良くなった時だけ promotion を許す。

### 掟

> Worktree の免責は master の免責ではない。
>
> Shadow の成功は production の許可ではない。
>
> Telemetry は verdict ではない。
>
> Age is a wake-up, not a verdict.

---

## 9. 完了条件

この wave の完了は「忘却が動いた」ではない。

完了は次の状態。

- heartbeat が 72h shadow burn-in を通った。
- forgetting proposals が canonical mutation なしで複数 snapshot 取れた。
- FULL vs SHADOW_GARAGE の paired A/B が再現可能になった。
- critical safety metrics が悪化していない。
- improvement が noise envelope を超えたか、超えなかったかを honest に報告できる。
- PROMOTE / HOLD / REJECT のいずれでも、測定結果から説明できる。

**改善が無ければ HOLD/REJECT が成功である。**

この実験の目的は機能を増やすことではなく、蒸留蔵が長く暮らすために、本当に役立つ代謝だけを選ぶことである。
